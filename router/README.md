# Router: a Cudy WR3000 (OpenWrt)

A **read-only** mirror of the router's config. Generated by `router-sync`
(`system/net/router.nix`), never edited by hand.

## Why this exists

The router is the piece of infrastructure Nix does not reach: 6 MB of flash and
128 MB of RAM put NixOS out of scale. Until 08/08/2026 the ~750 lines of UCI
lived only on the device, with no review, no history, and nobody knowing when
they changed. This does not make the router declarative; it makes the config
**visible** and the drift **detectable**, which is what was missing.

## Usage

```sh
router-sync diff   # compares device against repo; exits 1 if they diverge
router-sync pull   # brings the device's state into the repo
```

After touching anything through LuCI or through `uci set`, run `pull` and
commit. The `diff` is what keeps this directory from becoming a copy that used
to be true.

`diff` answers whether the mirror equals the DEVICE. Whether it equals the
REPO is a different question, and `router-ssot` answers that one: it fails when
a value this repo declares (the subnets, the Moonlight sources and ports, the
FAI routes, the sshd port) stops matching what the router repeats. It runs in
the pre-commit hooks and reads only this directory, never the device. See
[`../docs/notes/repo/router-ssot.md`](../docs/notes/repo/router-ssot.md).

**`sudo uci commit` leaves /etc/config as 0600.** Measured 19/08/2026: committing `dhcp`
and `network` through sudo left both files root-only, while `firewall`, untouched that day,
stayed 0644. The symptom on the next read is `uci: I/O error` for the normal user, and it
breaks `router-sync`, which reads UCI over SSH as that user and NOT as root. The repair is
`chmod 644` on whatever was committed. Suspect this first when a `pull` cannot read a config
it read the day before.

## What is NOT here

**Secrets.** The seven credential values come out redacted (rule 12): the
WireGuard private key, the PPPoE password, the two WiFi passwords, the LuCI
login, the adblock API password and the etherwake one. The redaction is
*fail-safe*: it redacts by default everything whose name suggests a credential
and only releases what it recognizes as public (`public_key`) or as a file path.

**Pushing.** `router-sync` does not write to the router, on purpose. Applying
UCI over SSH requires commit-confirm (apply, schedule a rollback, confirm only
if there is still access), otherwise one wrong network line locks you out and
the way back is failsafe mode with physical access. The decision about the push
tool is open in `docs/open-items.md`.

**What is not UCI.** `authorized_keys`, `/etc/sudoers.d/`, `~/bin/owfetch` and
`/etc/profile.d/99-owfetch.sh` live outside UCI and remain manual steps,
documented in the same TODO entry.

## Surviving an upgrade

Measured in the device's `keep.d` on 08/08/2026 (38 entries): `sysupgrade`
already preserves the whole `/etc/config/`, `/etc/profile.d/`, `/etc/dropbear/`,
passwd/shadow/group **and `/etc/sudoers.d/`**.

What stays out and needs to enter the router's `/etc/sysupgrade.conf`:

- `/home/v1cferr/`, where the SSH key and `~/bin/owfetch` live
- `/etc/sysupgrade.conf`, **itself**. `list_static_conffiles` reads the paths
  listed inside it but does not include it, so without that line the 1st upgrade
  preserves what you asked for and the 2nd loses everything.
